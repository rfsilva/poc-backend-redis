Redis Cache com Spring Boot - Guia Prático

Introdução

Este documento explica como o Redis é utilizado como solução de cache na nossa aplicação Spring Boot. O Redis (Remote Dictionary Server) é um armazenamento de estrutura de dados em memória, usado como banco de dados, cache e message broker.

Por que usar Redis para cache?

  • Performance: O Redis armazena dados em memória, proporcionando tempos de resposta extremamente rápidos.
  • Persistência: Apesar de ser um banco em memória, o Redis oferece opções de persistência.
  • Estruturas de dados versáteis: Suporta strings, hashes, listas, conjuntos e muito mais.
  • Expiração automática: Permite definir TTL (Time-To-Live) para entradas de cache.
  • Escalabilidade: Pode ser facilmente escalado horizontalmente.

Configuração do Redis no Spring Boot

1. Dependências

Primeiro, adicionamos a dependência do Spring Data Redis no arquivo pom.xml:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

2. Configuração do Redis

A classe RedisConfig configura o Redis como provedor de cache:

@Configuration
@EnableCaching
public class RedisConfig {

    @Value("${spring.redis.host:localhost}")
    private String redisHost;

    @Value("${spring.redis.port:6379}")
    private int redisPort;

    @Value("${spring.cache.redis.time-to-live:3600}")
    private long timeToLive;

    @Bean
    public LettuceConnectionFactory redisConnectionFactory() {
        RedisStandaloneConfiguration configuration = new RedisStandaloneConfiguration(redisHost, redisPort);
        return new LettuceConnectionFactory(configuration);
    }

    @Bean
    public RedisTemplate redisTemplate(RedisConnectionFactory connectionFactory) {
        RedisTemplate template = new RedisTemplate<>();
        template.setConnectionFactory(connectionFactory);
        template.setKeySerializer(new StringRedisSerializer());
        template.setValueSerializer(new GenericJackson2JsonRedisSerializer());
        template.setHashKeySerializer(new StringRedisSerializer());
        template.setHashValueSerializer(new GenericJackson2JsonRedisSerializer());
        return template;
    }

    @Bean
    public RedisCacheManager cacheManager(RedisConnectionFactory connectionFactory) {
        RedisCacheConfiguration config = RedisCacheConfiguration.defaultCacheConfig()
                .entryTtl(Duration.ofSeconds(timeToLive))
                .serializeKeysWith(RedisSerializationContext.SerializationPair.fromSerializer(new StringRedisSerializer()))
                .serializeValuesWith(RedisSerializationContext.SerializationPair.fromSerializer(new GenericJackson2JsonRedisSerializer()))
                .disableCachingNullValues();

        return RedisCacheManager.builder(connectionFactory)
                .cacheDefaults(config)
                .build();
    }
}

3. Propriedades de Configuração

No arquivo application.properties, configuramos o Redis:

# Redis Configuration
spring.redis.host=localhost
spring.redis.port=6379
spring.cache.type=redis
spring.cache.redis.time-to-live=3600000
spring.cache.redis.cache-null-values=false

Implementação do Cache

Anotações de Cache

O Spring fornece várias anotações para gerenciar o cache:

Anotação Descrição Uso na Aplicação
@Cacheable Armazena o resultado do método em cache Usado em findById para evitar consultas repetidas ao banco
@CachePut Atualiza o cache com o resultado do método Usado em update para manter o cache atualizado
@CacheEvict Remove entradas do cache Usado em delete para remover entradas obsoletas
@Caching Combina múltiplas operações de cache Usado para operações complexas que afetam múltiplos caches

Exemplo de Implementação

Veja como implementamos o cache no PersonService:

Busca por ID com Cache

@Cacheable(value = "personCache", key = "#id", unless = "#result == null")
public PersonDTO findById(Long id) {
    log.info("Fetching person with id {} from database", id);
    Person person = personRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("Person not found with id: " + id));
    return convertToDTO(person);
}

Nota: A anotação @Cacheable armazena o resultado em cache. Na próxima chamada com o mesmo ID, o método não será executado e o resultado será recuperado diretamente do cache.

Atualização com Cache

@CachePut(value = "personCache", key = "#id")
public PersonDTO update(Long id, PersonDTO personDTO) {
    log.info("Updating person with id: {}", id);
    Person existingPerson = personRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("Person not found with id: " + id));
    
    // Atualiza os campos
    existingPerson.setName(personDTO.getName());
    existingPerson.setBirthDate(personDTO.getBirthDate());
    existingPerson.setEmail(personDTO.getEmail());
    existingPerson.setAddress(personDTO.getAddress());
    existingPerson.setPhoneNumber(personDTO.getPhoneNumber());
    
    Person updatedPerson = personRepository.save(existingPerson);
    return convertToDTO(updatedPerson);
}

Nota: A anotação @CachePut executa o método e atualiza o cache com o resultado. Isso garante que o cache esteja sempre sincronizado com o banco de dados.

Remoção do Cache

@Caching(evict = {
    @CacheEvict(value = "personCache", key = "#id"),
    @CacheEvict(value = "allPersonsCache", allEntries = true)
})
public void delete(Long id) {
    log.info("Deleting person with id: {}", id);
    Person person = personRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("Person not found with id: " + id));
    personRepository.delete(person);
}

Nota: A anotação @CacheEvict remove entradas do cache. Aqui, removemos a entrada específica e também limpamos qualquer cache de lista que possa conter a pessoa excluída.

Melhores Práticas para Uso do Redis

1. Escolha Cuidadosa do que Cachear

Nem todos os dados devem ser cacheados. Considere:

  • Frequência de acesso aos dados
  • Custo computacional para obter os dados
  • Frequência de alteração dos dados
  • Tamanho dos dados

2. Defina TTL (Time-To-Live) Apropriado

O TTL deve ser definido com base na volatilidade dos dados. Dados que mudam frequentemente devem ter TTL menor. Em nossa aplicação, definimos um TTL padrão de 3600 segundos (1 hora).

3. Use Chaves de Cache Eficientes

As chaves de cache devem ser:

  • Únicas e específicas
  • Curtas, mas descritivas
  • Estruturadas de forma consistente

4. Invalidação de Cache

Mantenha o cache sincronizado com o banco de dados:

  • Use @CachePut para atualizar o cache após modificações
  • Use @CacheEvict para remover entradas obsoletas
  • Considere a invalidação em cascata quando necessário

5. Monitoramento

Monitore o uso do cache:

  • Taxa de acertos (hit rate)
  • Uso de memória
  • Tempo de resposta

6. Serialização Eficiente

Escolha serializadores eficientes para minimizar o tamanho dos dados e o tempo de serialização/desserialização. Em nossa aplicação, usamos GenericJackson2JsonRedisSerializer para valores e StringRedisSerializer para chaves.

Considerações sobre SOLID e Clean Code

Princípio da Responsabilidade Única (SRP)

Nossa implementação separa claramente as responsabilidades:

  • A configuração do Redis está isolada em RedisConfig
  • A lógica de negócios está no PersonService
  • O acesso aos dados está no PersonRepository

Princípio Aberto/Fechado (OCP)

A implementação do cache é extensível:

  • Podemos adicionar novos caches sem modificar o código existente
  • A configuração do cache é parametrizada via propriedades

Princípio da Inversão de Dependência (DIP)

Dependemos de abstrações, não de implementações concretas:

  • Usamos interfaces como CacheManager e RedisConnectionFactory
  • A injeção de dependência é usada para fornecer implementações

Clean Code

Seguimos práticas de código limpo:

  • Nomes descritivos para métodos e variáveis
  • Comentários explicativos onde necessário
  • Métodos pequenos com responsabilidade única
  • Uso de lombok para reduzir boilerplate
  • Logging adequado para facilitar a depuração

Conclusão

O Redis é uma excelente solução de cache para aplicações Spring Boot, oferecendo alta performance e flexibilidade. Quando implementado seguindo as melhores práticas, pode melhorar significativamente o desempenho da aplicação, reduzindo a carga no banco de dados e melhorando os tempos de resposta.

Lembre-se: O cache é uma otimização, não uma solução para problemas de design. Certifique-se de que sua aplicação funciona corretamente sem cache antes de implementá-lo.
